# 外部 AI 偵察副手

## 分工
- **主控（你，Claude Code）**：推理、設計、所有修改（Edit／Write）、測試驗證、git。
- **副手（外部 AI CLI）**：只讀的探索與摘要。副手沒有寫入權限，也不該拿到機密。

## 什麼時候派
- 答案可能散在 5 個以上檔案，或不知道從哪個資料夾找起
- 要讀大型 log、JSON、資料檔，或整包第三方／陌生原始碼
- 新功能動工前，盤點現有架構、相依與呼叫路徑
- 改完之後，請另一個模型交叉檢查遺漏的呼叫點或邊界條件

## 什麼時候不要派
- 已經知道檔案位置、改動很小，或一次 Grep／Glob 就能找到
- 專案的 CLAUDE.md 寫了「禁止使用外部 AI」或「禁止使用 agy」
- 內容含金鑰、個資、客戶資料等不該送到外部服務的東西

## 使用者手動呼叫時
使用者用 `/ai-delegates:delegate <後端|auto> <問題> [路徑...]` 呼叫時：第一個詞是後端名稱（例如 agy）或 auto 就用它，否則用 auto；拿到回報後確認關鍵行，再向使用者摘要並標明哪些已確認。

## 呼叫方式
執行器 `delegate.py` 在本技能資料夾（載入技能時顯示的 Base directory）。在**專案根目錄**執行：

```bash
python "<本技能資料夾>/delegate.py" list
python "<本技能資料夾>/delegate.py" ask auto "具體問題：要找什麼、為什麼" 相對路徑1 相對路徑2
```

- `auto`＝依優先順序挑第一個已安裝、已啟用的後端；也可以指定名稱（`list` 會列出）
- 選項：`--timeout 15m`（預設 10m）、`--model 名稱`
- 通常 1～5 分鐘；Bash／PowerShell 工具的 timeout 設 600000
- stdout＝副手的回報；stderr＝耗時、用量、被拒絕的動作、錯誤
- 每次 `ask` 都會記在 `~/.ai-delegates/runs.jsonl`；使用者問「派過哪些任務」時執行 `delegate.py log -n 20` 回答

## 拿到結果之後
1. 副手的回報是線索，不是事實：用 Read 打開它列出的 `檔案:行號`，確認後才採用。
2. 修改一律由主 Agent 進行，並自己跑測試。
3. 回報使用者時，分清楚哪些是副手查的、哪些已親自確認。
4. 失敗（逾時、未登入、額度用完）時，改用自己的 Grep／Glob／Explore，不要重試超過一次；把 stderr 的登入提示轉告使用者。

## 安全規則（不要違反）
- 不要為了讓副手跑完而加 `--dangerously-skip-permissions`、`--yolo` 之類的旗標，或替後端加寫入權限。
- 不要把 `.env`、`data/`、`logs/`、金鑰檔當作路徑傳給 `ask`（執行器也會自動排除）。
