# 角色派工：主控與副手

## 角色
每個角色用哪個 AI 由使用者設定（`/ai-delegates:setup`，或終端機 `delegate.py setup`）：

| 角色 | 做什麼 |
|---|---|
| `lead` | 主控：理解需求、規劃步驟、判斷 |
| `search` | 跨檔案搜尋、追呼叫路徑 |
| `log` | 大型 log／JSON／資料檔 |
| `explore` | 導讀陌生或第三方程式碼 |
| `review` | 改完後交叉檢查 |

所有修改（Edit／Write）、測試、git 一律由你（Claude Code）做；外部 AI 只有唯讀權限，也不該拿到機密。

## 先查角色交給誰
執行器 `delegate.py` 在本技能資料夾（載入技能時顯示的 Base directory）。在**專案根目錄**執行：

```bash
python "<本技能資料夾>/delegate.py" route <角色>
```

輸出 JSON：`{"role", "backend", "model", "self", "source"}`。
- `self: true`：這個角色就是你自己。副手角色用內建子代理（Explore 或 general-purpose），`model` 有值就照它設（haiku／sonnet／opus）。
- `self: false`：交給 `backend`，照下面的方式派工。
- 設定錯誤（後端停用、未安裝）會直接報錯：把訊息轉告使用者，請他執行 setup，不要自己換別的後端。

## 主控不是你時（`route lead` 的 self 為 false）
非小事的任務（要改 2 個以上檔案、要做設計判斷）動手前：
1. `python "<本技能資料夾>/delegate.py" plan "使用者的需求原文＋你知道的背景" 相關路徑...`（Bash timeout 設 900000）
2. 主控回傳：需求理解、要改的位置、步驟（每步怎麼驗證）、風險、需要使用者決定的事。
3. 「需要使用者決定的事」不是「無」時，先問使用者再動手。
4. 照計畫執行，每步自己驗證。計畫和實際程式不符（行號不對、函式不存在、測試失敗）時，停下來告訴使用者差異，不要硬照做，也不要自己悄悄改方向。
5. 回報時分清楚：主控規劃了什麼、你實際做了什麼、驗證結果。
小事（改一行、明確的錯字、使用者已經講清楚怎麼改）不用 plan。

## 什麼時候派副手
- 答案可能散在 5 個以上檔案，或不知道從哪個資料夾找起 → `search`
- 要讀大型 log、JSON、資料檔 → `log`
- 整包第三方／陌生原始碼、新功能動工前盤點架構 → `explore`
- 改完之後請另一個模型交叉檢查遺漏的呼叫點或邊界條件 → `review`

## 什麼時候不要派
- 已經知道檔案位置、改動很小，或一次 Grep／Glob 就能找到
- 專案的 CLAUDE.md 寫了「禁止使用外部 AI」或禁止某個後端
- 內容含金鑰、個資、客戶資料等不該送到外部服務的東西

## 派副手
```bash
python "<本技能資料夾>/delegate.py" ask <角色> "具體問題：要找什麼、為什麼" 相對路徑1 相對路徑2
```
- 第一個參數可以是角色（依設定）、後端名稱（指定）或 `auto`（依 priority 挑第一個可用的）
- 選項：`--timeout 15m`（預設 10m）、`--model 名稱`（優先於角色設定）
- 通常 1～5 分鐘；Bash／PowerShell 工具的 timeout 設 600000
- stdout＝回報；stderr＝耗時、用量、被拒絕的動作、錯誤
- 每次 `ask`／`plan` 都記在 `~/.ai-delegates/runs.jsonl`；使用者問「派過哪些任務」時執行 `delegate.py log -n 20`

## 使用者手動呼叫時
`/ai-delegates:delegate <角色|後端|auto> <問題> [路徑...]`：第一個詞是角色、後端名稱或 auto 就用它，否則用 auto；拿到回報後確認關鍵行，再向使用者摘要並標明哪些已確認。

## 拿到結果之後
1. 回報是線索，不是事實：用 Read 打開它列出的 `檔案:行號`，確認後才採用。
2. 修改一律由你進行，並自己跑測試。
3. 回報使用者時，分清楚哪些是副手／主控查的、哪些已親自確認。
4. 失敗（逾時、未登入、額度用完）時，改用自己的 Grep／Glob／Explore，不要重試超過一次；把 stderr 的登入提示轉告使用者。主控 plan 失敗時告訴使用者，問要不要改由你自己規劃。

## 安全規則（不要違反）
- 不要為了讓副手跑完而加 `--dangerously-skip-permissions`、`--yolo` 之類的旗標，或替後端加寫入權限。
- 不要把 `.env`、`data/`、`logs/`、金鑰檔當作路徑傳給 `ask`／`plan`（執行器也會自動排除）。
