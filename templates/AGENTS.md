# 派工規則（ai-delegates）

> 給「自己就是主控」的 AI CLI 用（例如 Codex CLI 讀 AGENTS.md）。把這段放進專案的 AGENTS.md，
> 並把 `<delegate.py 路徑>` 換成 ai-delegates 安裝位置的 `skills/delegate/delegate.py`。

你是這個專案的主控：理解需求、規劃、修改、測試都由你做。需要大範圍、只讀的偵察時，可以派給其他 AI 副手，節省你的 context。

## 角色交給誰
每個角色用哪個 AI 由使用者設定（終端機執行 `python <delegate.py 路徑> setup`）。派工前先查：

```bash
python <delegate.py 路徑> route <角色>
```

角色：`search`（跨檔案搜尋、追呼叫路徑）、`log`（大型 log／JSON）、`explore`（陌生或第三方程式）、`review`（改完後交叉檢查）。
`lead` 是主控，也就是你自己，不用派。

## 派工
```bash
python <delegate.py 路徑> ask <角色> "具體問題：要找什麼、為什麼" 相對路徑1 相對路徑2
```
- 通常 1～5 分鐘，指令 timeout 至少 10 分鐘
- stdout＝副手回報（關鍵位置 `檔案:行號`、核心邏輯、修改方向、不確定之處）；stderr＝耗時、用量、錯誤

## 什麼時候派
- 答案可能散在 5 個以上檔案、不知道從哪找起
- 大型 log、JSON、資料檔；整包陌生原始碼
- 改完之後請另一個模型交叉檢查

## 什麼時候不要派
- 已知檔案位置、改動很小、一次搜尋就找得到
- 專案規定禁止使用外部 AI，或內容含金鑰、個資、客戶資料

## 拿到結果之後
1. 副手的回報是線索不是事實：打開它列的 `檔案:行號` 確認後才採用。
2. 修改與測試由你自己做。
3. 回報使用者時分清楚哪些是副手查的、哪些你已確認。
4. 失敗（逾時、未登入、額度用完）時改用自己的搜尋，不要重試超過一次。

## 安全
- 副手只有唯讀權限；不要替它加寫入或略過權限的旗標。
- 不要把 `.env`、`data/`、`logs/`、金鑰檔當作路徑傳給副手。
